# Security model

Shade assumes the repository and its dependency metadata can be malicious.

## Git and filesystem

- Fetch/import first receive into a daemon-owned `0700` quarantine, validate every reachable commit tree, and only then promote through explicit fully-qualified refspecs; `refs/shade/*` never participates.
- Managed imports contain their own objects and have no permanent alternates or hardlinks.
- Submodules, Git LFS, custom filters, tracked `.env*` and detected secret contents are rejected before checkout/checkpoint. Large blobs are streamed through a bounded scanner; ancestor trees are checked even when the tip deleted the file.
- Managed worktrees install required internal Git filters. The persistent content filter scans the complete request before returning any bytes to Git, with an anonymous private spill file for inputs above 1 MiB. Ordinary porcelain, including `git add -f`, fails before Git writes a detected secret blob. Safe bytes pass unchanged in both clean and smudge directions.
- `context` is an observational fast path: one porcelain-v2 status call reports HEAD and change counts without a full policy inventory. Every retention or integration boundary—checkpoint, fork, sync, resolution, publish, release and GC—performs the fail-closed inventory before it can create an object/ref or move a branch.
- Production materialization requires successful APFS clone syscalls on the same filesystem. There is no copy fallback.
- Whole-directory cloning is restricted to verified, immutable daemon-owned bases/layers with at most 25,000 inventoried entries and no internal hardlinks. Agent-owned workspaces always use controlled traversal. Symlinks remain symlinks, special filesystem objects are rejected before cloning, and destination publication never replaces an existing tree.
- Worktrees are detached and locked. Synthetic checkpoint objects are private retention anchors, not remote branches.

## Dependencies

Shade uses exact host tool paths, versions and executable digests but never installs a toolchain. Fingerprints omit absolute paths and credentials. JavaScript installers run frozen with scripts disabled; Python accepts only hashed wheels under `uv.lock` and never installs the project; Cargo and Go only populate/verify their native download caches. Every provider performs an online fill followed by an offline replay where applicable. Replay runs through macOS `sandbox-exec` with network operations denied for the process tree. A failure to apply isolation fails preparation. Bun uses that OS guarantee because its install CLI has no offline flag; the other providers also keep their native offline flags.

Executable configuration, missing/stale locks, Python source builds, VCS/path/editable Python sources, dependency-added Python startup code, unapproved JS lifecycle scripts, `build.rs`, proc macros and Go build/generate actions are either statically rejected or never invoked by Shade. Python preparation first creates an empty environment with the pinned uv/interpreter, records its bootstrap files, and rejects any changed bootstrap file or additional startup hook after wheel installation.

TOML, YAML and JSONC locks/configuration are inspected structurally. Corepack proxies resolve only to already installed matching packages. npm/pnpm run with their exact Node interpreter; receipts include interpreter identity. Runtime provisioning declarations and executable hooks are rejected. pnpm retains its separate metadata and policy-verification cache between online fill and offline replay; security policies remain enabled.

The [configuration boundary](DEPENDENCY-CONFIGURATION.md) also isolates external npm/uv/Cargo configuration during preparation. Python requires stable uv >=0.11.16 and disables executable keyring providers. Cargo's sandbox hides parent/native-cache configuration and pins rustc. Go parses local workspace/replacement declarations with its own read-only JSON commands inside the COW probe and rejects paths outside it.

JavaScript lifecycle consent lives in the daemon database and is bound to provider/package/version/integrity. Repository metadata cannot grant it. Approval and revocation commit with the operation result and outbox; decisions apply to new preparations, while current workspaces retain their bytes. Approved hooks run on COW build stages with pinned Node/shell, network denied and writes limited to their package and isolated temporary directories. Existing hardlinks are detached; nested dependencies remain protected. The dependency graph determines hook order. pnpm installation paths are resolved from the locked importers/snapshots, including aliases and peer variants; graph paths and dependency names are validated before invoking a manager. Root/workspace hooks never enter a reusable artifact. See [script approvals](SCRIPT-APPROVALS.md) for commands and scope.

## Secrets

Shade rejects trees containing a path whose basename starts with `.env`, including `.envrc` and `.environment`, or content recognized by its local detector. The detector recognizes private-key headers, selected GitHub/Slack/Google/Stripe/OpenAI token formats, credential-bearing URLs and sufficiently varied credential assignment literals. Detection is heuristic; it does not recognize every possible credential. The same scanner handles binary data and signatures spanning read boundaries, returning only a decision.

Fetch/import validate all reachable history in a private quarantine; checkpoint and publish revalidate HEAD, the real index and the candidate working tree before creating private refs or moving a branch. Checkpoint tree creation uses a private index snapshot whose paths and blobs are validated before `write-tree`, so concurrent Git index replacement cannot bypass that check. Current private working files are excluded from checkpoint staging and copied separately into forks/successors with `0600` permissions, including when a tracked file's safe Git version differs from its private working contents. Read-only status bypasses the content filter so it can report those changes without writing blobs.

Baselines live under the private Shade root with mode `0600`; their files occupy a separate directory from the manifest, so arbitrary private filenames cannot replace metadata. Directories and the socket are user-only. Review payloads contain only relative filenames, key names and one of `parent`, `child`, `unchanged`, `removed` or `conflict`. Values, fragments and hashes never enter public responses or logs. Dotenv merging preserves comments and assignment formatting. JSON objects and TOML tables merge recursively, with JSON Pointer key paths in previews; scalar/array edits and deletion conflicts remain explicit. One-sided changes preserve exact bytes. Opaque/binary files support keep/discard and one-sided merges; divergent edits remain pending before a successor is allocated. A merge writes a successor; it never edits an active parent.

GC performs secret discovery even for a workspace whose lease has already been released. Changes requiring review produce a `review.required` event containing the key-only preview and block deletion. Keep/discard decisions and their operation outcomes commit atomically; reviewed merges commit their handoff atomically. Review resolution can retain or discard a released/orphaned view without releasing a different current workspace's lease. Each decision is fenced by an immutable `0600` private snapshot. Changes to reviewed bytes supersede a pending review; changes after a completed discard require a new review before GC. Public events still contain only paths/key names/outcomes. Snapshots and incomplete snapshot staging are cleaned with their owning workspace or at startup.

V1 is not a same-UID process sandbox. A linked worktree necessarily exposes a writable common Git object database to normal Git commands, and a process that can both read a secret and run arbitrary Git plumbing can bypass attributes with commands such as `git hash-object -w --no-filters`. Git has no mandatory pre-object-write hook; a LaunchAgent runs as the login user; owner-controlled permissions and flags do not separate those processes. The clean filter is therefore an accidental-commit guardrail, not a security boundary against a malicious local actor. Shade will refuse to consume or publish a contaminated tree, but it cannot identify the original pathname of an unreferenced blob written directly by that actor. An absolute information-flow guarantee would require removing raw Git access or introducing a broker under a distinct security principal, both outside the closed V1 assumptions.
